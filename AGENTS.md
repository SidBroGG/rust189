# AGENTS.md — Руководство и правила разработки для AI-агентов

> **ВАЖНО**: Этот файл является обязательным к строгому соблюдению всеми AI-агентами, работающими над проектом. Отклонения от описанных правил и архитектуры недопустимы.

---

## 1. Суть проекта

Разработка высокопроизводительного, оптимизированного клиента Minecraft 1.8.9 на языке **Rust**.
- **Основная ориентация**: соревновательные мини-игры на серверах (Hypixel, Bedwars, Skywars, Duels и др.).
- **Главные приоритеты**: максимальный FPS (минимизация 1% и 0.1% Low), минимальный input lag, стабильность сетевого соединения, 100% честная механика движения/коллизий 1.8.9 (полная совместимость с серверными античитами: Watchdog, GrimAC, Vulcan).
- **Ключевой функционал**:
  - Автоматическая загрузка оригинальных ассетов Minecraft 1.8.9 из Mojang CDN при первом запуске в папку рядом с исполняемым файлом.
  - Полная реализация протокола Minecraft 47 (версия 1.8.9).
  - Поддержка только Offline аккаунтов (генерация оффлайн UUID через MD5).
  - Полная кастомизация интерфейса (HUD): перемещение элементов по экрану с привязкой к настраиваемой сетке (Snap-to-Grid), масштабирование, цвет фона и прозрачность.
  - Поддержка ресурспаков 1.8.9 и текстурных расширений (CTM, CIT, Custom Colors).
  - Двухэтапная поддержка шейдеров: нативный быстрый WGSL-рендерер ландшафта, а затем поддержка внешних optifine шейдерпаков.
  - Полное сохранение всех настроек графики, биндов клавиш и профилей интерфейса в конфигурационные файлы (TOML).

## 2. Технологический стек

- **Язык**: Rust (2021 edition, свежая стабильная версия).
- **Графика**: `wgpu` (WebGPU на Rust, современный кроссплатформенный графический API: DirectX 12, Vulkan, Metal).
- **Окна и ввод**: `winit`.
- **Интерфейс (UI)**: `egui` (`egui-wgpu`, `egui-winit`) со стилизацией под Minecraft (пиксельный шрифт, текстуры виджетов, кастомный snap-to-grid редактор).
- **Асинхронность и сеть**: `tokio` (полнофункциональный асинхронный рантайм для сетевого TCP ввода-вывода).
- **Математика**: `glam` (быстрые SIMD-векторы и матрицы).
- **Звук**: `rodio` (высокоуровневый кроссплатформенный аудио-движок).
- **Конфигурация**: `serde`, `serde_json`, `toml`.

## 3. Референсные исходники (`ref/`)

В корне репозитория расположена папка `ref/`:

- `ref/net/minecraft/` — оригинальные декомпилированные исходные коды Minecraft 1.8.9 (MCP).

## 4. Пайплайн разработки на каждом шаге

Перед реализацией любой функции или подсистемы агент **ОБЯЗАН** следовать трехшаговому пайплайну:

```
[1. Исследование в MCP] ───> [2. Оптимизация под Rust] ───> [3. Реализация в Rust]
  Смотрим референс в           Проектируем структуры данных   Пишем идиоматичный,
  ref/net/minecraft/...        без сборщика мусора (GC)       типобезопасный код
```

1. **Посмотреть реализацию в оригинале**:
   - Найти соответствующий класс в `ref/net/minecraft/` (например, для физики — `EntityPlayer.java`, `AxisAlignedBB.java`; для чанков — `Chunk.java`; для пакетов — `net/minecraft/network/play/...`).
   - Изучить порядок полей, формулы расчета, последовательность тиков и краевые случаи.
2. **Оптимизировать и сократить под Rust**:
   - Избавиться от наследования Java и аллокаций в куче в пользу Rust-структур, `enum`, `traits` и компактных представлений в памяти (Data-Oriented Design).
   - Использовать SIMD (`glam`), битовые маски и flat arrays вместо громоздких объектов.
   - Использовать zero-copy парсинг пакетов через `bytes::Bytes` и срезы памяти везде, где возможно.
3. **Написать код на Rust**:
   - Написать чистый, задокументированный и строго типизированный код в соответствующем крейте.
   - Покрыть код модульными тестами.
   - Не оставляй упоминания о minecraft, hypixel, optifine, minecraft minigames

## 5. Незагруженная архитектура проекта (Cargo Workspace)

Проект организован в виде легковесного Cargo Workspace без избыточных абстракций:

```
rust189/
├── Cargo.toml                  # Workspace корневой манифест зависимостей
├── PLAN.md                     # Генеральный план разработки с чекбоксами
├── AGENTS.md                   # Данный файл правил для агентов
├── ref/                        # Референсы (protocol-47.json, MCP исходники 1.8.9)
├── crates/
│   ├── protocol/               # Кодек протокола 47, VarInt, NBT, шифрование, пакеты
│   ├── world/                  # Воксельный мир, хранилище чанков, AABB, физика
│   ├── render/                 # wgpu конвейер, мешер чанков, атлас текстур, шейдеры
│   ├── gui/                    # egui интерфейс, виджеты Minecraft, HUD-редактор сетки
│   ├── assets/                 # Загрузчик ассетов с Mojang CDN, парсер ресурспаков
│   └── client/                 # Главный бинарник: игровой цикл, ввод, сеть, конфиги
```

### Зоны ответственности крейтов:
1. **`protocol`**: Чистая сериализация и десериализация сетевых данных. Не зависит от графики или физики. Пакеты строго типизированы.
2. **`world`**: Представление мира, чанков (секции 16x16x16), палитры блоков, точные AABB коллизии и расчет физики движения игрока по MCP 1.8.9.
3. **`render`**: Все взаимодействие с `wgpu`. Мешинг чанков (Cull-face/Greedy), рендеринг геометрии, WGSL-шейдеры, Frustum Culling.
4. **`gui`**: Интеграция `egui`. Рендеринг пиксельных шрифтов, меню, худа, редактора сетки.
5. **`assets`**: Работа с сетью и диском для скачивания/кэширования ванильных файлов Minecraft (Client Jar, Index, Ogg-звуки, lang).
6. **`client`**: Точка входа (`main`), объединяющая сеть Tokio, игровой цикл (20 тиков/сек физики) и кадры отрисовки `winit`.

## 6. Пайплайн тестирования после каждого этапа

После выполнения каждого этапа в обязательном порядке выполняется двухуровневое тестирование:

### Уровень 1: Автоматизированное тестирование
- `cargo check --workspace` — отсутствие ошибок компиляции во всех крейтах.
- `cargo test --workspace` — прохождение всех модульных и интеграционных тестов (сериализация VarInt, NBT парсинг, расчеты AABB, валидация хэшей ассетов).

### Уровень 2: Интерактивное тестирование с участием человека (Human-in-the-Loop)
- Агент формирует **человекочитаемый чек-лист проверки** (например: запустить `cargo run -p client`, убедиться в отсутствии артефактов интерфейса, проверить пинг сервера в списке серверов, проверить перемещение HUD-блока мышью).
- Пользователь подтверждает успешность проверки перед переходом к следующему этапу.

## 7. ЖЕЛЕЗНОЕ ПРАВИЛО: ТОЛЬКО ОДИН ЭТАП ЗА ОДИН ЗАПРОС

> **КРИТИЧЕСКИ ВАЖНО**:
> **Агент имеет право выполнять РОВНО ОДИН этап из `PLAN.md` за один запрос пользователя!**

1. За один запрос агент берет следующий невыполненный этап плана (например, **Этап 1**).
2. Выполняет все пункты и подпункты только этого этапа.
3. Запускает тесты и проверку компиляции (`cargo test`, `cargo check`).
4. Обновляет отметки `[x]` для выполненных пунктов в `PLAN.md`.
5. Предоставляет пользователю краткий отчет о выполненном этапе и чек-лист для проверки человеком.
6. **Останавливает работу и ждет подтверждения и следующей команды от пользователя.**
7. Категорически **ЗАПРЕЩЕНО** начинать следующий этап без явного запроса пользователя.
